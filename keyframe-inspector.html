How to read the results

A keyframe (also called a sync sample or I-frame) is a frame stored as a complete picture. Every other frame is stored as a change from nearby frames, so a player cannot start decoding from an arbitrary frame; it has to start at a keyframe. A lossless splitter copies compressed data without re-encoding, so each new part must begin on a keyframe. That is why the Actual start column is never later than Planned start: the splitter steps back to the nearest keyframe at or before the time it planned.

The keyframe interval is the gap between consecutive keyframes. Many phone and screen-recording apps produce an interval of about one to two seconds, so cuts land close to the plan. Some exports use ten seconds or more, and then a cut can land that much earlier than planned. If your longest interval is large, expect uneven part lengths; the inspector shows this before you split anything. Our keyframe explainer covers the background, and the format glossary defines the other terms on this page.

The frame rate shown is the average (frame count divided by duration), so variable-frame-rate recordings such as screen captures may show a non-round number. If a file reports no keyframe table, the container has no sync-sample list and the inspector treats every frame as a keyframe, which is what the MP4 specification says to assume.

What this inspector does not do

It reads standard (non-fragmented) MP4, MOV and M4V files only. Fragmented MP4 files store their index in many small pieces across the file; the splitter can read those, but this page will tell you it cannot. It reports the first video track and the first audio track, and it does not decode any video, so it cannot judge visual quality. Planned cut points use the same rule as the splitter (target length is the midpoint of your min and max); the split planner explains that rule and estimates file sizes.
