Is my video uploaded? Check for yourself

How the tool handles your file, what the website does load from the internet, and a two-minute test that confirms the video stays on your device.

Last updated: 3 October 2026

Reel Cutter says your video never leaves your device. You should not have to take that on trust, and with a browser's developer tools you do not have to. This page explains how the tool handles your file, what the website does load from the internet, and a two-minute test you can run yourself.

The short answer

No. When you choose a video, the page reads it from your own storage using the browser's built-in file access. The splitting, the zip packing and the download all happen inside the page, and the tool's code contains no network requests: no uploads, no calls to a server. You can read the code yourself by opening “view source” on the home page, because it is plain JavaScript written inline in the page.

How the tool handles your file

  1. Choosing. The browser gives the page a reference to the file on your device. The file is not copied anywhere.
  2. Reading. The tool reads small slices of the file: first the index that describes where each frame is, then the frame data it needs for each part.
  3. Building. It assembles each part as a new MP4 in the tab's memory, then bundles them into a zip, also in memory.
  4. Handing back. When you press “Download zip”, the page creates a temporary link that starts with blob:. Those links only exist inside your browser and point at data in your own tab.

What the website does load from the internet

Being precise matters here. When you open the site, your browser downloads the page itself, its stylesheet and a small script, from the site's hosting provider. The pages also include Google's AdSense loader script, because the site is set up to show ads in future. That script comes from Google, not from us, and it is described in the privacy policy. The site does not run its own analytics script. None of these requests contains your video, and the video-splitting code does not interact with them.

The hosting provider may keep ordinary technical logs of page requests, such as IP address and requested page, as most websites do. Those logs record that someone visited a page, not what is on your device.

Test it yourself in two minutes

Option 1: watch the network

  1. Open the split tool in a desktop browser.
  2. Open developer tools: press F12 (or Ctrl+Shift+I on Windows and Linux, Cmd+Option+I on a Mac).
  3. Go to the Network tab and click the clear button so the list is empty.
  4. Choose a video, run the split and download the zip.
  5. Look at the list. You should not see any upload (a request with the method POST or PUT) and nothing whose size is close to your video's. What you will see is the page's own files, Google's ad script, and an entry starting with blob: for the preview player. That last one is a local address inside your browser, not a network upload. All of them are tiny compared with your video.

Option 2: go offline

  1. Load the split tool page.
  2. Turn off your Wi-Fi or switch on airplane mode.
  3. Choose a video and run the split.

Because the page has already loaded and the splitting needs no server, it should still run with no connection. A tool that uploaded your video could not do that.

What this does and does not guarantee

The tool's own code does not send your video anywhere. We cannot vouch for things outside the page, such as a browser extension that reads every page you visit, or malware on your device. If your footage is truly sensitive, use a browser profile with extensions disabled, and run the offline test above.

Why this design?

Processing locally is faster for big files because there is no upload or download wait, it keeps private recordings private, and it means the site has no stored user videos to protect or delete. The trade-off is that your browser's memory sets the limits, which is covered in splitting video on a phone and the troubleshooting guide.
