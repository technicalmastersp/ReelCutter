Troubleshooting common errors

What each error message actually means, why it happens, and the fastest way to fix it — organized by symptom.

Reel Cutter reads your video's container format directly and copies compressed samples into new files without re-encoding. That's what makes it fast and lossless, but it also means it depends on the source file being structured in a way it can understand. This page covers every error you're likely to see, what's actually happening under the hood, and how to fix it.

"This is a fragmented MP4 (streaming-style)..." or parsing failures

Standard MP4 files store one master index of every video and audio sample. Fragmented MP4s — common from browser-based recorders, some screen-capture tools, and streaming pipelines — instead split that index across many small chunks throughout the file. Reel Cutter supports both formats. If you still see a parsing error, the file most likely uses an unsupported or non-standard variant:

  • Re-export as a standard MP4. Opening the file in any free editor (like the built-in editor on your phone, or a tool like HandBrake) and re-saving as MP4 normalizes the container structure.
  • Check for file corruption. If the file was interrupted mid-transfer or mid-recording (a crashed recording app, a phone that ran out of storage mid-capture), the container's index itself may be incomplete. A re-export can sometimes recover it; if the source app has an "repair" or "recover" option for interrupted recordings, try that first.
  • Confirm the file extension matches the actual format. A file renamed from something else to .mp4 without actually being converted will fail to parse — check the file's real format with your OS's built-in file info/properties panel.

"Could not find a usable video track in this file"

This means Reel Cutter read the container successfully but didn't find a video track it recognizes — usually because the file is audio-only, uses an unsupported video codec, or the video track's metadata is missing or malformed. Confirm the file actually contains video (play it back first), and if it does, try re-exporting it with a standard codec like H.264 or H.265, which cover the vast majority of source footage from phones, cameras, and screen recorders.

Browser tab crashes or freezes partway through

Because processing happens entirely in your browser's memory rather than on a server, very long or very high-resolution files can use more memory than a browser tab is allowed. This shows up differently depending on your device:

  • On phones, background apps and other open tabs compete for the same limited memory pool. Close everything else, then try again.
  • On 4K or multi-hour source files, even a capable laptop can hit limits. Try lowering the source resolution first in your camera app or a free converter, or split the source into two rough halves and process each half separately.
  • On older or low-memory devices, a desktop browser (Chrome, Firefox, Edge, Safari) on a laptop will generally handle larger files more reliably than a phone browser.

Output parts are a few seconds off my requested length

This isn't a bug — it's an inherent trade-off of lossless, byte-copy splitting. See our full explainer on why cuts snap to keyframes for the technical reason and how to tighten the drift.

Split parts won't play, or play with a garbled first second

If a part plays with a brief glitch or corrupted-looking frame right at the start, the most common cause is an unusual keyframe flag in the source file that made a cut point look valid when it wasn't quite. Try re-exporting the source file as a standard MP4 first (this normalizes keyframe flags) and re-run the split — if the issue persists on a specific file, it likely uses an edge-case encoder variant that isn't fully supported yet.

Audio is missing or out of sync in a part

  • Missing audio: Confirm "include audio" is checked in the split settings before running — Reel Cutter lets you strip audio intentionally for video-only exports.
  • Out-of-sync audio: This is rare with byte-copy splitting since audio and video are aligned independently per part, but can happen if the source file itself already had drifting audio sync before you split it — check the original file's playback to confirm.

Source-specific notes

iPhone / iOS camera recordings
Generally split cleanly as standard or fragmented MP4/MOV. If you've applied Live Photo or Cinematic mode effects, export a standard video copy first (Share → Save as Video, or trim once in the Photos app) before splitting.
Android camera recordings
Most stock camera apps export standard MP4 with H.264/H.265 video, which splits reliably. Some manufacturer camera apps use non-standard containers for high-frame-rate or HDR modes — if a specific recording mode fails to parse, try a recording made in the default/standard mode as a comparison.
Screen recordings (OBS, QuickTime, built-in phone screen recorder)
OBS and most screen recorders export standard or fragmented MP4/MOV that Reel Cutter reads directly. Longer keyframe intervals are common in screen recordings (static content compresses well without frequent full-frame refreshes), which can mean more drift on split boundaries — see the keyframes explainer for why.
Zoom, Google Meet, and other video-call recordings
Cloud-recorded calls download as standard MP4 and generally split without issue. Locally recorded calls occasionally use a fragmented structure — Reel Cutter supports this, but if a specific file still fails, re-exporting once through a free converter usually resolves it.
Older camcorder / digitized tape exports
Capture devices vary widely in export quality. If a digitized file fails to parse, re-exporting it once through a free tool like HandBrake (which normalizes the container) before splitting resolves the vast majority of cases.

Still stuck?

If none of the above resolves it, reach out via the contact page with the file's original format (camera/app/export source), roughly how long the video is, and the exact error text shown in the tool's log — that's usually enough to identify what's happening.
